## 0. 왜 지금 필요한가 — 측정한 것

패턴 22종, 보스 24종이 이미 들어가 있고 패턴 없는 보스는 없다. 그런데 재보니
**세 가지가 겹쳐서, 보스는 많은데 싸움은 몇 종류 안 된다.**

### 문제 1 — 최종 티어 보스 넷이 사실상 같은 보스다

| 보스 | 2페이즈 패턴 |
|---|---|
| 북부 타이탄 | coreBurst + ruinCharge + callPack |
| 중부 거상 | coreBurst + ruinCharge + callPack |
| 서부 몰락왕 | coreBurst + ruinCharge + callPack |
| 남부 심연존재 | coreBurst + tentacleLash + callPack |

클라이맥스 넷이 같은 패턴이면 지역을 다 도는 이유가 "재료가 다르다"뿐이 된다.
동부 고룡만 `dragonBreath + ruinCharge + spiritCleanse`로 조금 다르다.

### 문제 2 — 필러 패턴 셋이 게임 전체를 채우고 있다

24보스 기준 `quakeRoar` 12회, `chargeRush` 11회, `groundSlam` 10회.
절반 이상의 보스가 이 셋 중 둘을 갖고 있다.

### 문제 3 — 회피 방식이 사실상 한 가지다

패턴 종류(kind) 분포가 circle 13 / line 4 / cone 3 / cleanse 1 / summon 1.
**60%가 "원에서 벗어나기"** 다. 예고 장판을 보고 옆으로 굴러 나오는 동작을
싸움 내내 반복하게 된다.

지금 구조가 나쁜 게 아니라 **축이 하나뿐**이다. 축을 늘려야 보스마다 다른
싸움이 된다.

## 1. 새 패턴 축 — "장판 피하기" 말고 무엇을 시킬 것인가

기존 축은 전부 **위치**다(여기 서지 마라). 다른 축을 넷 더 연다.

| 축 | 요구하는 것 | 새 kind |
|---|---|---|
| 위치 (기존) | 지금 서 있는 곳을 벗어나라 | circle / line / cone |
| **추격** | 계속 움직여라. 멈추면 따라잡힌다 | `tracking` |
| **거리** | 붙어라 / 떨어져라. 중간이 최악이다 | `band` |
| **표적** | 본체 말고 저것부터 부숴라 | `pillar` |
| **순서** | 순서대로 터진다. 경로를 읽어라 | `chain` |

각 축은 "동료가 자동으로 대응할 수 있는가"를 만족해야 한다
(`BOSS_DESIGN.md` §5 — 자동 동료 2명이 있으므로 혼자 이해 가능한 구조 우선).
동료 AI는 이미 `dodgeDangerZone`으로 장판을 피하므로, 새 축도 **위험 지대를
표현할 수 있는 형태**로 설계한다.

### 1-1. `tracking` — 따라오는 장판

- 예고 후 터지는 게 아니라, **플레이어를 천천히 따라오는 위험 구역**이 생긴다.
- 이동 속도는 플레이어보다 느리다(예: 60%). 계속 걸으면 안 맞는다.
- 대신 그동안 다른 패턴이 겹쳐 들어온다 → "피하면서 딜할 자리를 찾는" 압박.
- 지속시간이 끝나면 사라진다. 못 피하면 계속 맞는다(즉사는 아니다).

**동료 AI**: 기존 `dodgeDangerZone`이 매 틱 위치를 다시 보므로 그대로 작동한다.

### 1-2. `band` — 거리 요구

- **근접 금지형**: 보스 주변 반경 R 안이 위험. 붙으면 계속 맞는다 → 원거리 강제.
- **원거리 금지형**: 반경 R **밖**이 위험. 떨어지면 맞는다 → 근접 강제.
- 둘을 번갈아 쓰면 "붙었다 떨어졌다"가 리듬이 된다.

이 축이 중요한 이유: 지금 게임은 원거리 직업이 일방적으로 유리한 구간이
생기기 쉽다. 원거리 금지 구간이 있으면 근접이 유리한 순간이 생긴다.

### 1-3. `pillar` — 부숴야 멈추는 것

- 보스가 기둥/촉수/제단 같은 **부술 수 있는 대상**을 소환한다.
- 그게 살아 있는 동안 보스는 특정 패턴을 계속 쓰거나, 피해를 덜 받는다.
- 제한 시간 안에 못 부수면 큰 피해.

기존 `summon`(callPack)과 다른 점: 소환물이 **싸우는 적**이 아니라
**꺼야 하는 스위치**다. 타깃을 옮기게 만드는 게 목적이다.

### 1-4. `chain` — 순서대로 터진다

- 장판 여러 개가 동시에 깔리되 **터지는 시각이 다르다.**
- 순서를 읽으면 안전한 경로가 보인다. 무작정 굴러다니면 다음 것에 맞는다.
- 예고 색/밝기로 순서를 표현한다(구현 시 `fireAt` 차이를 시각화).

이건 기존 `zones` 구조로 **거의 그대로 된다** — `bornAt`/`fireAt`을 어긋나게
깔면 끝이다. 새 kind가 아니라 기존 kind의 배치 규칙에 가깝다.

## 2. 지역 보스 5종 — 각자 다른 싸움

각 보스가 **주 축 하나 + 보조 축 하나**를 갖는다. 필러 패턴(quakeRoar 등)은
1페이즈 초반에만 쓰고, 2페이즈는 그 보스의 축으로만 굴린다.

### 북부 · 타이탄 — 부위 공략 (주: `pillar` / 보조: 위치)

`BOSS_DESIGN.md` §4에 이미 방향이 있다: 부위 공략 → 자세 붕괴 → 약점 노출.

- 다리 두 짝이 `pillar`로 취급된다. 둘 다 부수면 **자세 붕괴**(그로기 진입).
- 자세 붕괴 중에는 모든 패턴이 멈추고 약점(핵)이 노출된다.
- 시간이 지나면 다시 일어서고 다리 내구도가 회복된다 → 화력 집중 타이밍 싸움.
- 보조로 발구르기(circle)를 써서 다리 근처에 계속 있기 어렵게 만든다.

**요구하는 것**: 타깃 전환과 화력 집중 타이밍.

### 남부 · 심연 존재 — 오염 확산 (주: `tracking` / 보조: `chain`)

- 지나간 자리에 **오염 장판이 남는다.** 시간이 지나도 안 사라진다.
- 전장이 서서히 좁아진다 → 오래 끌수록 설 자리가 없다. 속전속결 압박.
- 촉수가 `chain`으로 순서대로 내려친다 → 좁아진 공간에서 경로를 읽어야 한다.
- 정화 수단(동부 반지, 특성 등)이 있으면 장판 일부를 지울 수 있다.

**요구하는 것**: 시간 관리. 이 보스만 "빨리 죽여야 하는" 싸움이다.

### 동부 · 고룡 — 거리 전환 (주: `band` / 보조: 위치)

- 자세를 둘 오간다.
  - **비행 자세**: 근접이 닿지 않는다. 원거리만 유효, 대신 지상에 브레스 장판.
  - **착지 자세**: 반경 밖이 위험(꼬리 휩쓸기). 붙어야 안전.
- 자세 전환 예고가 있고, 전환 순간에 위치를 잘못 잡으면 크게 맞는다.

**요구하는 것**: 거리 조절. 파티 전체가 같이 붙었다 떨어졌다 해야 한다.

### 서부 · 몰락왕 — 저주 누적 (주: `chain` / 보조: `pillar`)

- 서부 지역 효과(공포 → 이탈)와 이어진다. 패턴에 맞을 때마다 **저주가 쌓인다.**
- 저주가 임계를 넘은 동료는 전장을 이탈한다 → 인원이 줄어든다.
- 제단(`pillar`)을 부수면 저주가 일부 씻긴다. 부수러 가면 본체 딜이 멈춘다.
- 패턴은 순차 폭발(`chain`)이라 무작정 구르면 저주가 빨리 쌓인다.

**요구하는 것**: 손실 관리. 딜을 멈추고 정화하러 갈지 판단하는 싸움.

### 중부 · 거상 — 과열 (주: `band` / 보조: `pillar`)

- 중부 지역 효과(폭염)와 이어진다. **열 게이지**가 계속 오른다.
- 보스 주변 반경 안은 더 빨리 오른다(근접 금지형 `band`).
- 냉각탑(`pillar`)을 켜면 반경 안에서 열이 내려간다. 다만 그 위치가
  보스 패턴 사거리 안이다.
- 열이 만렙이면 큰 피해 + 행동 불능.

**요구하는 것**: 자원(열) 관리와 위치 선택의 충돌.

## 3. 필드 보스는 어떻게 두는가

지역 보스는 위처럼 기믹형으로 가되, **필드 보스는 지금 형태를 유지한다.**
필드 보스는 지나칠 수 있는 선택 콘텐츠라(`EQUIPMENT_DESIGN.md` §9) 기믹을
이해해야 넘어갈 수 있으면 "선택"이 아니게 된다.

다만 필러 편중은 필드 보스에서도 고친다:

- `quakeRoar`/`chargeRush`/`groundSlam`은 **보스당 최대 하나**만.
- 종족 색이 드러나는 패턴을 하나씩 더 만든다
  (거미 = 거미줄 지대, 뱀 = 조이기 추격, 오니 = 연속 베기 등).

## 4. 구현 순서 제안

데이터 주도라 대부분 `BOSS_PATTERN_DEFS`에 항목을 추가하는 일이다.

1. **`chain`** — 새 코드가 거의 필요 없다. 기존 zone에 `fireAt`을 어긋나게
   깔면 된다. 여기서 "순서를 읽는 싸움"이 되는지 먼저 확인한다.
2. **`band`** — zone 판정을 반전(`inverted: true`)하면 원거리 금지형이 된다.
   동료 AI의 `dodgeDangerZone`이 반전 구역에서도 옳게 움직이는지 확인 필요.
3. **`tracking`** — zone에 추적 대상과 속도를 붙인다. 매 틱 위치 갱신.
4. **`pillar`** — 가장 크다. 부술 수 있는 개체 + 그게 살아 있는 동안의
   보스 상태 변화가 필요하다. 타이탄 부위 공략과 같이 설계한다.

각 단계마다 지켜야 할 것:

- **회피 가능성 불변식**: `예고시간(초) × 이동속도 > 탈출 거리`.
  이미 테스트로 잠겨 있다(circle/line/cone). 새 kind도 같은 테스트에 넣는다.
- **등록만 하고 배선을 빠뜨리지 말 것.** 패턴을 정의만 하고 핸들러를 안 붙이면
  조용히 아무 일도 안 일어난다. 이 프로젝트에서 여러 번 겪었다.
  "값이 세팅됐나"가 아니라 "체력이 실제로 깎였나"로 테스트한다.

## 5. 아직 안 정한 것

- 타이탄 부위 파괴의 구체 수치(부위 내구도, 자세 붕괴 지속, 회복 시간)
- 남부 오염 장판이 전장을 얼마나 빨리 좁히는지 — 너무 빠르면 화력 체크가 되고,
  느리면 없는 것과 같다
- 서부 저주 임계와 제단 정화량 — 지역 효과의 저주 누적과 수치를 맞춰야 한다
- 중부 열 게이지가 지역 폭염 효과와 같은 값을 쓰는지, 보스 전용인지
- 2페이즈 외형 변화(`BOSS_DESIGN.md` §6)를 어디까지 그릴지 — 모델 작업과 묶인다
